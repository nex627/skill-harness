# PDCA 适配指南

## PDCA 基础

PDCA = Plan-Do-Check-Act，戴明环。Skill Harness 用它作为 skill 创建和执行的核心骨架。

```
P（计划）→ D（执行）→ C（检查）→ A（沉淀）
    ↑                                    │
    └────────────────────────────────────┘
                  闭环迭代
```

## 四阶段详解

### P — Plan（计划）

**目标**：杜绝凭空决策。

| 做什么 | 怎么做 | 阈值 |
|--------|--------|------|
| 读历史 | L3 私有库 | ≥3条 |
| 看对标 | L2 行业库 + 外部搜索 | ≥3个 |
| 定方案 | 整合需求 + 历史 + 对标 | 完整 |

**阻断**：信息不足则阻断，不跳过。

### D — Do（执行）

**目标**：结构化交付，不简略。

三段式：
1. **D1 摘要** — 做什么、为什么这么做
2. **D2 交付物** — 完整产出
3. **D3 偏差** — 和计划的差异

**禁止**：一步式简略输出。

### C — Check（检查）

**目标**：草稿不直接生效。

双层：
1. **AI 自检** — 格式 + 逻辑 + 可用性 + 边界，≥80分
2. **人工复核** — 人确认后才通过

**驳回**：退回 D 阶段，不退 P 阶段。

### A — Act（沉淀）

**目标**：经验可复用。

1. 效果评估
2. 踩坑记录（≥3条）
3. 写入 L3
4. 版本号

## 多模型叠加

PDCA 是基础骨架，不同场景可叠加专属模型：

| 场景 | 叠加 | P | D | C | A |
|------|------|---|---|---|---|
| 短视频/热点 | + OODA | 观察热点 | 快速响应 | 数据反馈 | 快速迭代 |
| 电商运营 | + DMAIC | 定义测量 | 分析改进 | 控制验证 | 标准化 |
| 产品设计 | + 设计思维 | 共情用户 | 原型设计 | 用户测试 | 迭代优化 |
| 代码开发 | + DevOps | 需求分析 | 编码实现 | 测试部署 | 线上复盘 |
| 增长运营 | + AARRR | 获客分析 | 激活留存 | 转化数据 | 传播优化 |

## 阻断机制

```
阶段未通过 → 标记 BLOCKED → 保存当前产出 → 修正后从当前阶段继续
```

特点：
- 不从头开始（断点续跑）
- 阶段间强依赖
- C 阶段驳回只退 D，不退 P

## 断点续跑

```
P_RUNNING → P_BLOCKED → 修正 → P_RUNNING → P_DONE
                                              ↓
D_RUNNING → D_BLOCKED → 修正 → D_RUNNING → D_DONE
                                              ↓
C_RUNNING → C_BLOCKED → 修正 → C_RUNNING → C_DONE
                                              ↓
A_RUNNING → A_DONE → COMPLETED
```

## 与三层知识库的关系

|------|------|------|

| D | — | — |
| C | — | — |
| A | — | L3（踩坑）+ L2（通用经验，审核后） |
