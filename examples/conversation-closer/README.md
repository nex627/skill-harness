# 对话收尾示例

> **类型**：对话级通用 C+A 引擎
> **适用场景**：所有对话的收尾检查、多步骤任务的交付核验与记忆沉淀

## 这是什么

对话收尾是一个**通用门控型 skill**，它不做具体业务，而是为所有其他 skill 提供统一的：

- **C 阶段引擎**：交付核验（检查产物是否齐全、结构是否合规）
- **A 阶段引擎**：记忆沉淀（写入 wiki、更新 short-term、补充 raw）

## 为什么需要

在日常对话中，最常见的两个问题：

1. **记忆遗漏**：重要结论聊完就忘了，没沉淀到知识库
2. **交付遗漏**：多步骤任务只做了第一步就报告"完成"，后续产物全漏了

对话收尾用**机制**解决这两个问题，而不是靠 AI 自觉。

## 核心思路：三级分级

不是所有任务都需要重型流程。对话收尾自动判断级别：

| 级别 | 场景 | 流程 |
|------|------|------|
| 一级·轻量 | 简单问答 | 只做记忆沉淀 |
| 二级·中量 | 多步骤任务 | 交付核验 + 记忆沉淀 |
| 三级·重型 | 标准化业务 | 完整 Workflow Harness PDCA |

## 典型用法

### 用法1：对话结束时自动收尾

```
用户：今天先到这
AI：（自动激活对话收尾）
  → 扫描本次对话是否有需要写入 wiki 的结论
  → 有 → 写入战略记录/工作进度/需求记录...
  → 更新 short-term
  → 补充 raw（如果有情绪或重点产出）
  → 完成，回复用户
```

### 用法2：多步骤任务交付核验

```
用户：早（触发晨报）
AI：（启动晨报任务，自动声明交付清单）
  交付清单：
  1. 原始数据 sources.json
  2. 原文 md
  3. 8段解读 MD
  4. HTML 报纸版
  5. 索引维护
  6. 口头交付
  
  → 执行各步骤...
  → 准备报告"完成"前，自动激活交付核验
  → 逐项检查：文件存在？结构合规？
  → 有缺项 → 继续补齐，不报告完成
  → 全部通过 → 进入记忆沉淀 → 报告完成
```

## 与其他 skill 的关系

```
各业务 skill（晨报、文档蒸馏、开发管理...）
  ↓ 各自定义
  P 阶段：怎么规划
  D 阶段：怎么执行
  验收清单：什么算完成
  ↓
对话收尾 skill（通用 C+A 引擎）
  ↓ 统一提供
  C 阶段：按验收清单核验
  A 阶段：按沉淀规则入库
```

**核心原则：各 skill 定义"什么算完成"，对话收尾负责"检查是否真的完成"。**
